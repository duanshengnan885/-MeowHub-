# 2026-09-06 Bug 修复与经验归档 (Phase 0 固本止损)

## 记录 1：内置浏览器网址输入使用原生 prompt 弹窗违规 (F9)
- **现象**：点击工具栏内置浏览器按钮弹出浏览器自带的 `prompt()` 丑陋原生输入框，破坏桌面沉浸感与主题一致性。
- **根因**：前期快速实现时直接调用了浏览器原生 `prompt()` API。
- **修复**：在 `index.html` 中新增主题化模态窗 `url-input-modal`（复用现有 `.modal-box` 现代毛玻璃样式），在 `app.js` 中新增 `showUrlInputModal`/`closeUrlInputModal`/`confirmUrlInputAction`，支持回车键确认及 URL 协议前缀自动纠错。
- **教训**：严守零原生弹窗底线，所有输入/确认组件一律使用星喵统一的 Soft-Cute 主题化 Modal/Toast。

## 记录 2：OS Agent 具备硬删除物理毁伤风险 (P2)
- **现象**：AI 操控系统的 `delete_item` 操作调用 `shutil.rmtree` 或 `os.remove` 进行物理粉碎删除，用户无法撤销找回。
- **根因**：未接入系统级回收站机制。
- **修复**：将物理删除逻辑替换为 `send2trash.send2trash(path)`，并在 `requirements.txt` 中正式确立 `send2trash>=1.8` 依赖，操作提示明确标明已移入回收站。
- **教训**：涉及用户本地数据的破坏性操作必须具备安全兜底，禁止物理不可逆直删。

## 记录 3：OS Agent 权限开关仅为 UI 壳、后端零执行 (P3)
- **现象**：前端虽然有「询问/检测/完全控制」开关，但后端 `api.py` 完全未检查该配置，高危指令无条件静默执行，且 PowerShell 默认请求管理员权限。
- **根因**：版本迭代中配置项未与后端执行入口建立联动绑定。
- **修复**：在 `execute_os_action` 入口加设止损闸门，当 `agent_control_level == "ask"` 时，拦截 `delete_item`、`write_file`、`run_powershell`、`run_python` 四类高危动作；取消 PowerShell 默认管理员提权（`run_as_admin=False`）。
- **教训**：任何安全相关的用户设置，前后端必须同步闭环，严禁空挂配置。

## 记录 4：配置直写覆盖存在半写损坏与无备份风险 (P5)
- **现象**：`save_all_configs` 直接用 `open("w")` 覆盖写盘，若发生写中断可能导致核心配置损坏置空。
- **根因**：缺乏原子写入与自动备份机制。
- **修复**：在 `config.py` 中引入 `_atomic_save`（写临时文件 .tmp -> 刷盘 -> 滚动复制 .bak -> `os.replace` 原子替换），并在 `load_all_configs` 中增加容灾回退逻辑，当主文件损坏时自动从 `.bak` 恢复；同时在 `.gitignore` 中加入 `*.bak` 与 `*.tmp` 防泄密。
- **教训**：所有核心持久化状态必须原子落盘，且容灾机制能从备份自愈。

## 记录 5：重开程序后历史会话中的智能体深度思考过程丢失
- **现象**：当使用支持深度思考的大模型（如 DeepSeek-R1/Reasoner、Kimi-K2.6 等）完成回复时，当前界面能看到思考过程折叠框；但关闭软件重新打开后，思考过程完全消失，只留下最终正文。
- **根因**：
  1. 流式推理结束存盘（`handleStreamEnd`）时，`activeSession.history.push` 仅存入了 `content: window.activeContentText`，而将流式累积的 `window.activeReasoningText` 直接丢弃，未写入持久化历史中；
  2. 历史会话恢复（`loadSessionChatHistory`）时，渲染逻辑仅检索 `msg.content` 中是否存在 `<think>` 标签，完全未对 `msg.reasoning` / `msg.reasoning_content` 进行判定与渲染；
  3. 新建气泡时 `#active-reasoning-box` 缺少默认 `display: none`，非思考模型或初始化状态下存在样式空框隐患。
- **修复**：
  1. 在 `handleStreamEnd` 中，提取并持久化保存 `reasoning` 字段至 `activeSession.history`（同时兼顾 OS Agent 的 `osAssistantMsg` 路径以及 `<think>` 标签模型）；
  2. 重构 `loadSessionChatHistory`：优先取 `msg.reasoning` / `msg.reasoning_content` 渲染专属主题化折叠框 `.chat-reasoning-box`，若缺失则向前兼容解析 `content` 中的 `<think>`，并自动剥除正文中的旧标签防重复；
  3. 在 `style.css` 中补齐 `.chat-reasoning-box` 与 `.chat-reasoning-content` 萌系毛玻璃样式及明暗主题支持；
  4. 在 `api.py` 的多轮会话拼接时，自动过滤历史 assistant 中的 `<think>` 标签，防止污染多轮上下文及浪费 Token。
- **教训**：所有前端临时流式状态（如思考过程、工具调用过程等）若属于用户需要回溯的上下文，必须规范落入数据模型协议（`history`）中，确保「生成即持久化、持久化即完整还原」。

## 记录 6：思考过程背景色过深导致字体对比度极低看不清
- **现象**：在默认樱花粉（Sakura）及浅色主题下，模型深度思考折叠框展开后背景为暗色深蓝黑，而文本颜色继承了全局暗紫红 `--text-color: #831843`，黑底紫字导致文字完全看不清。
- **根因**：
  1. `.chat-reasoning-box details` 和 `.chat-reasoning-content` 采用了固定暗色背景（`rgba(15, 23, 42, 0.6)` 和 `rgba(0, 0, 0, 0.25)`），未与当前主题联动；
  2. 样式中仅单向覆盖了 `body[data-theme="light"]`，而默认樱花粉（`body` 及 `body[data-theme="sakura"]`）未获覆盖，直接落入暗黑底色；
  3. 文本颜色使用 `color: var(--text-color)`，在明色主题下该颜色为深色字体，叠在暗色背景上对比度严重不足。
- **修复**：
  1. 为各主题（Sakura、Light、Cyberpunk、Retro、Forest、Ocean、Sunset 及 Dark）抽象出思考框专属 CSS 变量（`--reasoning-box-bg`, `--reasoning-box-border`, `--reasoning-summary-color`, `--reasoning-content-bg`, `--reasoning-content-text`, `--reasoning-accent-border`）；
  2. 樱花与浅色主题下避免生硬刺眼的纯白卡片，采用温润通透的柔粉/浅岩灰微渐变底色（`rgba(255, 241, 245, 0.88)` / `#f1f5f9`）搭配浓郁深褐/深岩灰文字（`#4c1d2e` / `#1e293b`），对比度达 11.2:1，兼顾 Soft-Cute 萌系温润视觉与绝佳字迹清晰度；
  3. 暗色主题下采用深色背景与高亮亮色字体（`#e2e8f0` / `#a7f3d0` 等），确保全主题下思考文本均清晰易读；
  4. 增加思考中脉冲微动效（`thinkingPulse`）与平滑滚动条美化。
- **教训**：卡片容器背景与内部文字颜色必须成对使用同源主题变量约束对比度，严禁在全局主题系统中使用硬编码深色背景套用动态文本变量；浅色主题应追求温润自然的微色调融入，而非生硬冷涩的纯白填底。
## 记录 7：沙盒导入与差异对比混乱、无清空、无法覆盖及思考文本泄漏 (P0)
- **现象**：
  1. 导入沙盒时新内容盲目追加在旧内容之后，导入其他内容无法替换或取消之前的内容；
  2. 沙盒工具栏缺少清空操作，导入后无法一键清除沙盒内容及重置对比状态；
  3. 对比导入时，若消息包含深度思考过程，思考内容与输出结果发生混淆对比；若沙盒为空时对比无参照基准；
  4. 在编辑模式与对比模式来回切换时对比按钮被隐藏导致无法切回，Windows 平台换行符（CRLF vs LF）导致全量虚假差异行。
- **根因**：
  1. `importToSandbox` 采用了 `+= "\n\n---\n\n"` 累加拼接逻辑；
  2. 界面与脚本中缺少沙盒清空（`clearSandboxContent`）闭环；
  3. 标签剥除采用朴素 `indexOf`，对未闭合、大小写变体或 `<thought>`/`<reasoning>` 标签失效，且此前 `handleStreamEnd` 保存了未完全清洗的 `content`；沙盒为空时无历史对比基准；
  4. LCS `diffLines` 未做换行符标准化；`setSandboxMode('edit')` 将 `btnDiff` 设为 `display: none` 打破了模式切换闭环。
- **修复**：
  1. 沙盒工具栏增加 `🗑️ 清空沙盒` 按钮（`.modal-box` / 主题化按钮），并在 `app.js` 实现 `clearSandboxContent`，彻底清空 textarea、预览、diff 对比容器及内存状态；
  2. 改造 `importToSandbox` 为直接覆盖写盘（`textarea.value = cleanText`），切换为编辑模式并刷新实时预览；
  3. 封装 `window.getCleanMessageContent` 全局正则剥除函数，彻底剔除 `<think>`、`<thought>`、`<reasoning>` 等各类大小写及残缺未闭合的推理标签；在流式结束 `handleStreamEnd` 中严格清洗 `content` 并独立持久化 `reasoning`；
  4. 升级 `importToSandboxDiff`：沙盒有内容时对比「沙盒文本 vs 当前 AI 回复」；沙盒为空时智能回溯上一版本 AI 回复对比「上版正文 vs 当前正文」；既无沙盒又无上一版本时直接载入沙盒编辑模式，严密保证两端 0 思考内容泄漏；
  5. 优化 `diffLines` 标准化 `\r\n` 为 `\n`，增加空文本防护与 2500 行上限保护；保持模式双向可切换；`acceptDiffChange` 与 `rejectDiffChange` 彻底清理状态并联动更新实时预览。
