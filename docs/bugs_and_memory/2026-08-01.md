现象 → pywebview 桌宠使用 `-webkit-app-region: drag` 拖拽时，WinForms `SetWindowPos` 将宽高传入 `None` 导致 ctypes 崩溃；透明窗口 `hide()` 后 WebView2 恢复失败；托盘开启桌宠后保存主题会被陈旧 DOM 状态关闭。
根因 → 第三方 WinForms move 实现不兼容新版 ctypes；透明 Layered Window 物理隐藏会挂起 WebView2；前端保存把桌宠开关当作普通全量字段，覆盖了后台真实状态。
修复 → 在 `main.py` 启动前 monkey patch `BrowserForm.move` 传入 0 尺寸；`pet.html` 改为 Pointer Events + 后端原生移动；`api.py` 使用屏外驻留和强制重绘，后端维护桌宠状态；`app.js` 仅在用户明确改变开关时提交桌宠字段，后端再次过滤陈旧值。
教训 → 透明 WebView2 窗口应优先保活并屏外移动；跨入口状态必须由后端维护，前端只提交显式变更。

现象 → 主窗口/桌宠置顶切换不生效；点击关闭时前端确认框乱码并可能卡死。
根因 → 桌宠设置没有绑定实时 API；置顶逻辑分散且窗口句柄/类型处理不统一；closing 回调同步调用 `evaluate_js`，同时退出兜底文本被错误编码。
修复 → 统一 Win32 `SetWindowPos` 置顶 helper，补上桌宠置顶事件；关闭回调改用原生 Unicode `MessageBoxW`，彻底退出直接结束进程，前端兜底文案改为 Unicode 转义。
教训 → pywebview 的同步 closing 回调不能依赖 WebView2 JS；窗口层级操作必须复用同一套已类型化的 Win32 调用。
