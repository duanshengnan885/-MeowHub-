# 2026-08-08 更新日志

## UI 命名更改与结构调整
- **现象**：原设置界面的“展示与悬浮卡片”名称不够直观，同时“系统提示词及角色库”嵌套在“算法采样与提示策略”中层级过深。
- **根因**：初始设计时未充分考虑到功能独立性和命名的用户习惯。
- **修复**：
  1. 在 `ai_ui_assistant/index.html` 中，将“展示与悬浮卡片”更名为“桌宠”。
  2. 将“系统提示词及角色库”抽取为一个独立的、平级的一级折叠分类，优化层级结构。
- **教训**：功能分类应更贴近用户实际认知，重要的独立功能板块应该有独立的入口卡片。

## 弹窗组件替换优化（此前的更改）
- **现象**：进行删除会话、打包导出对话、以及写字沙盒导出等操作时，弹出了系统原生的白色警告框（alert）。
- **根因**：对应的方法（`deleteSession`, `exportChatLog`, `exportSandboxMarkdown`）中使用了 `window.alert()`。
- **修复**：
  1. 将所有的 `alert` 替换成了全局的 `showToast("...", "error")` 主题化气泡提示。
  2. 给导出成功的操作增加了 `showToast("✅ 导出成功！", "success")` 的提示。
- **教训**：在 UI 开发中应强制使用自定义的、符合主题设计的弹窗组件，避免原生 `alert` 破坏沉浸式体验。

## 通用设置与通道配置界面重构
- **现象**：`通用设置` 内包含了 `更新与通知` 和 `桌宠`，导致分类逻辑不清晰；同时通道密钥里的 `激活机型` 名字不够精简，且在选择名称极长的模型时会导致方框样式被撑爆。
- **根因**：原先菜单归类太深且未考虑到过长文本的溢出。
- **修复**：
  1. 将 `更新与通知` 和 `桌宠` 两个子级分类提取到了外层，变成了独立的 `level-1-card` 面板，提升了访问便捷度。
  2. 把 `激活机型` 的名称精简更名为 `模型`。
  3. 补充修复：将 `config-active-model` 外层包裹了 `div` 并设置 `overflow-x: auto`，配合父级 `min-width: 0`，彻底解决了原生 select 无法内建横向滚动条的问题。
- **教训**：在涉及用户可能会加载非标或极长名字的大模型（如自建的超长命名ollama模型）时，必须提前在 UI 层级加入自适应与滚动条控制（滑块条）。

## 提示词库大升级与自定义系统
- **现象/需求**：需要增加更多预设的角色提示词（包含各个职业），但原先所有提示词堆叠显示占用高度过长。并且用户需要能自定义提示词和命名的功能。
- **修复/更改**：
  1. 在 `config.py` 中内置了涵盖写手、翻译、精算师、医生、厨师、教练、侦探等 20 种详尽的专业级系统预设提示词。
  2. 在 UI 层面（`index.html` 和 `style.css`）将角色预设区变为高度受限的垂直滚动盒子（并定制了专属的半透明滚轮条 `.custom-scrollbar-y`），避免几十个按钮挤占满整个屏幕。
  3. 在预设区域下方新增了一个【➕ 保存当前提示词为自定义预设】的功能按钮。用户在文本框内书写完提示词后点击此按钮即可快速将其以星星 ⭐ 标记的形式永久保存为个人的常用预设并本地持久化记录。
- **教训**：在列表数据增加时必须及时引入滚动条机制，并在系统级预设之外提供用户自定义能力，保证极高自由度与体验感。

## 代理控制等级UI补充
- **现象/需求**：需要删除不再使用的“默认终端”设置项，并在主界面对话框上方（深度思考按钮前）增加一个包含“询问”、“检测”、“完全控制”三个等级的权限控制UI。
- **修复/更改**：
  1. 从 `index.html` 和 `app.js` 中彻底移除了 `config-default-terminal` 的相关配置区块与事件绑定。
  2. 在 `.chat-toolbar` 内新增了一个 `id="agent-control-level"` 的 `<select>` 下拉框，提供 ask, detect, control 三个级别，并赋予了半透明圆角样式。
  3. 在 `config.py` 和 `app.js` 中新增了 `agent_control_level` 字段进行数据的本地持久化存储。
- **教训**：淘汰旧配置时应连同前后端加载/序列化代码一并清理；针对工具栏组件的扩展，使用透明无边框的 `<select>` 能够保持界面风格的一致与紧凑。

## 提示词自适应显示与细节扩充
- **现象/需求**：1. 用户在“提示词 (System Prompt)”框里输入或选择了长内容后，单行 input 显示不全，无法上下拉伸。2. 20 个角色预设虽然有了，但内容过短，AI 无法有效发挥角色扮演能力。3. 对话框上方模型名字旁边希望能同步显示当前扮演的角色。
- **修复/更改**：
  1. 在 `index.html` 中，将 `#config-prompt` 从单行 `<input>` 升级为了 `<textarea>`，并设置了垂直拉伸属性 `resize: vertical`，加入了自定义滚动条，方便预览多行提示词。
  2. 在 `config.py` 中，全面扩充了所有 19 个新增默认角色的 System Prompt，从原本的一句话扩写成了包含“能力限定、行文风格、专业要求、回复框架”等多维度的长篇优质 Prompt，确保 AI 生成质量。
  3. 在 `app.js` 及其 `updateStatusBar` 函数中新增了角色名称匹配逻辑。当用户在右侧选择了某个提示词（或手动输入），系统会自动判断属于哪个设定（或显示自定义角色），并将其更新到界面聊天框的标题处（如 `🧠 DEEPSEEK | 📦 deepseek-chat | 🎭 代码专家`）。
- **教训**：在 UI 交互中，要确保多行文本框不仅能看，还能拉伸。给 LLM 配置的系统级人设一定要加入明确的格式与风格要求，否则容易出现 AI 出戏的情况。

## 升级完全控制智能体（OS Agent）
- **现象/需求**：用户希望“完全控制”的电脑控制智能体不再局限于简单的文件删除和浏览，而是能够真正实现联网、调用外部 API、主动执行脚本（成为一个真正的 Auto-Agent）。
- **修复/更改**：
  1. 重新设计了 `config.py` 中的 `系统操控智能体` System Prompt，极大增强了它的自主性和使命感。通过在提示词中详细列出 Python 隔离执行与 PowerShell 终端交互的示例，赋能它主动去执行网络请求（如请求天气 API 等）和复杂任务处理。
  2. 验证了底层的 `api.py` 中，`run_python` (通过 `_execute_python_code_sandbox`) 和 `run_powershell` 早已被支持，现在结合更强的 Prompt，它能真正在后台写脚本、抓数据，然后反刍结果并多轮思考直至完成任务。
- **教训**：底层的 API 工具箱（Tool Calling）搭建好后，必须配合结构完整、极具引导性的 System Prompt 才能释放其实力；智能体不是“被动”执行，而是要在提示词中明确告知它：遇到不懂的数据请自行写代码去外网拉取（ReAct思维）。


## 界面细节与管理面板清理优化
- **现象/需求**：算法采样参数无提示不易懂；模型绑定和PowerShell权限控制显得多余（用户希望默认最高权限）。
- **修复/更改**：
  1. 在 `index.html` 中为采样温度、最大 Token 等核心参数的滑块控制区域增加了 `title` 属性，实现悬停功能释义。
  2. 从 `index.html`, `app.js`, `config.py` 彻底移除了“对话模型绑定模式”和“PowerShell 执行权限”选项，并在底层的 `api.py` 中将 `run_powershell` 的执行固定为最高权限（admin）模式。
  3. 将【模型数据库管理】和【画图模型管理】无缝合并到了【通道与密钥授权】折叠面板中，将其重命名为【通道密钥与模型数据库管理】以整合相关功能，且修复了之前破坏 HTML 布局的问题。
- **教训**：过多的基础控制选项反而会让用户产生选择困难，能用底层统一高权限完成的就不要留给用户手动切换。
